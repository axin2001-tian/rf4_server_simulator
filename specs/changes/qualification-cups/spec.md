# 资格 / 活动分支完成奖杯

Status: in-progress

## Problem Statement

资格 1-8（永久）与活动 9-20（限时）的每个分支各有十几到二十条任务，全部完成后玩家没有任何奖励，进度条走满即结束。官服在分支完成时给一枚对应奖杯（如「纺车竿高手」「手竿高手」），并随渔获结算弹礼物卡；本服此前完全没有这条链路。

## Solution

玩家把某个分支的全部任务（不含未下发的缺口任务）做完时，对应奖杯直接进奖赏面板（3/16），系统频道播报获得；8 个永久分支全部完成再发一枚「超级高手」总杯。完成分支的那一尾鱼结算时，渔获界面弹出礼物卡显示这枚奖杯。老存档登录后一次性补齐历史已完成的奖杯。

## User Stories

1. 作为玩家，我希望分支任务全部完成后立刻拿到对应奖杯，以便奖赏面板有进度回报。
2. 作为玩家，我希望完成分支的那一尾鱼在渔获结算界面弹出礼物卡显示奖杯。
3. 作为老玩家，我希望登录后自动补齐补丁上线前已完成的分支奖杯，不必再钓一条鱼触发。
4. 边界：奖杯卖掉/丢掉不重发（发放记录在 `kv`，不看背包）。
5. 边界：含缺口任务的分支按已下发（非缺口）任务全完成判定——缺口任务不在面板上，不能拿玩家看不到的任务卡奖杯。
6. 边界：重放结算、重连、重复登录巡检都不重发。
7. 边界：8 个永久分支全完成后额外发总杯（不在活动分支完成时发）。

## Implementation Decisions

- 模块：`internal/gameserver/qualification_rewards.go`。
- 奖杯映射：20 个分支杯 + 总杯，item_id 与中文名逐条核对静态 `item_def`（category=72）与客户端本地化。
- 判定：`ensureQualificationCups` 遍历 `qualificationRules`，按 `ID/1000` 归分支，跳过 `eventGapRuleIDs`；分支内所有非缺口任务 `CompletedTS>0` 即完成。
- 发放：`grantQualificationCup` 用 `prepareNewItem("house")` + `beginEconomyTx`，kv 幂等键 `qual-cup:<uid>:<branch>`（0=总杯）与物品 `INSERT OR IGNORE` 同事务，抢到标记才发；已发返回 nil。
- 到账表现：聊天播报（一次巡检合并成一条，避免老档首登补发多枚时刷屏）+ 4/22 推送。奖赏物品 wire 树 `f4` 投影成 **14**（奖赏分组），不能用 house 的 10——客户端物品管理器按 f4 分组，3/16 处理函数把奖赏写死进分组 14。
- 结算礼物卡：分支杯随 `801.f4` 的 811 礼物行下发（复用升级礼物机制，与升级礼物可并存）。来源码固定 **2**（游戏活动），`f1` 给非 0。依据：客户端卡片取词函数（GameAssembly 0x180D4BD40，跳转表 0x180D4C04C）只有 1/2/4/5/6 有效，3 是空号（`ja` 越界目标，画不出卡）；`f1=0` 客户端整枚跳过。资格完成无专属来源码，取通用的 2。
- 调用点：14/4 结算后（本尾鱼可能让某分支达标）与 28/2 全量快照（登录兜底，覆盖补丁上线前的老存档）。
- 不改表结构、不改迁移、不改静态库。奖杯物品已存在于 `item_def`。
- 客户端基线 4.0.25034。回滚：删除 `qualification_rewards.go` 与两处调用即可，已发物品与 kv 标记保留在库里，回滚后不触发任何已有逻辑。

## Testing Decisions

- 接缝：真实 SQLite（`newStaticRigTestServer`）+ 行为链路；结算走 `evaluateQualifications` + `ensureQualificationCups`，读库用 `countPlayerCups`。
- 期望值来自 `item_def` 字面量与本尾鱼重量（1002 的 3000g 门槛），不由被测代码反推。
- 覆盖：分支集齐发杯、总杯条件、缺口分支按非缺口判定、item_id 与 `item_def` 逐条对齐、奖赏 f4=14 投影、重放不重发（连续两次巡检第二次返回空且物品行数不变）。
- 回滚后变红的测试：`qualification_rewards_test.go` 全部。

## Out of Scope

- 阶段礼物（每阶段/每任务的奖励）：无官服物品样本，不做。
- 官服资格专属弹窗（「恭喜您获得礼物」独立窗 / 节点礼物区）：走 5016 节点元数据 / 13020 礼物包另一套子系统，需官服报文样本，本 PR 不做；当前用通用来源码 2 的结算礼物卡显示奖杯。
- 奖杯可交易/可回收等经济玩法。

## Further Notes

- `[事实]` 分支杯 item_id 与中文名对齐 `item_def` category=72 与客户端本地化（如 `qual_spin_cup`=纺车竿高手、`reward_bday26`=俄钓4-九周年纪念）。
- `[事实]` 奖赏分组 14：3/16 响应处理函数 `bmnlpbpkedc.ogbnjjglplh`（RVA 0x1147EC0）`mov edx,0xe`。
- `[事实]` 811 来源码跳转表（PR #407 反汇编 + 实机校准）：有效 1/2/4/5/6，3 空号，`f1` 必须非 0。
- `[假设]` 官方资格奖杯同样在分支完成时发放；官服独立礼物窗未抓包，用结算礼物卡代替，语义与视觉可能不完全一致。
- `[推断]` 聊天播报复用 `pushSystemChat`（福袋、等级礼物已在用），真机表现一致；未单独抓包。
- 实测：本地清档，分支 1 集齐发杯，奖赏面板不重登即见杯；钓 ≥3kg 鱼完成分支后结算界面礼物卡渲染奖杯。
